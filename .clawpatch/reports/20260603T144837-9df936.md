## medium: Declared workspace entrypoint is missing the workspace manifest

id: fnd_sig-feat-ui-flow-22f9e2353f-7214_6a3803963a
category: build-release
confidence: high
triage: risk
status: open
feature: Apple project Grove.xcodeproj (feat_ui-flow_22f9e2353f)

evidence:
- Grove.xcodeproj/project.xcworkspace (project.xcworkspace)

The owned workspace bundle contains SwiftPM resolution metadata but no contents.xcworkspacedata file. That means the claimed entrypoint is not a valid Xcode workspace; a workspace-based build or inspection path such as xcodebuild -workspace Grove.xcodeproj/project.xcworkspace will reject it instead of discovering the Grove project and scheme.

recommendation:
Either add a valid Grove.xcodeproj/project.xcworkspace/contents.xcworkspacedata file that points at the project, or update build/discovery tooling to treat Grove.xcodeproj itself as the project entrypoint rather than using the internal workspace path.

test analysis:
No linked tests were provided for the workspace bundle shape, and target-level tests only run after Xcode has already accepted and resolved the project/workspace entrypoint.

suggested regression test:
Add a CI smoke check that verifies Grove.xcodeproj/project.xcworkspace/contents.xcworkspacedata exists and that xcodebuild -list can resolve the intended Xcode entrypoint.

minimum fix scope:
Workspace metadata only: restore the missing contents.xcworkspacedata file or change the semantic entrypoint/build scripts to use Grove.xcodeproj.

repro:
Run xcodebuild -list -workspace Grove.xcodeproj/project.xcworkspace; Xcode reports that the path is not a workspace file.

## medium: New Tab can attach a browser tab to any key window

id: fnd_sig-feat-ui-flow-01884210cd-cf19_a7727597c1
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Apple source Grove/App (feat_ui-flow_01884210cd)

evidence:
- Grove/App/AppDelegate.swift:50-63 (AppDelegate.newTab(_:))
- Grove/App/AppDelegate.swift:256-257 (AppDelegate.setupMainMenu())

The New Tab action only requires some key window, then uses that window as the tab host. The BrowserWindowController cast is optional and only affects the initial location, so if an About panel, help window, sheet, or other non-browser window is key, Cmd+T creates a BrowserWindowController and calls addTabbedWindow on the non-browser window. That can produce an invalid tab group or a no-op/leaked controller instead of opening a normal Grove browser window.

recommendation:
Require the key window to have a BrowserWindowController before tabbing. If it does not, fall back to newWindow(_:) or find the most recent visible BrowserWindowController and tab into that.

test analysis:
No linked tests were declared for AppDelegate, and the discovered BrowserCapabilityTests cover BrowserWindowController validation rather than AppDelegate menu dispatch with a non-browser key window.

suggested regression test:
Add an AppDelegate menu-flow test that makes a non-BrowserWindow key, invokes newTab(_:), and asserts Grove opens or selects a BrowserWindow rather than adding the browser window as a tab of the non-browser window.

minimum fix scope:
AppDelegate.newTab(_:) and, if needed, a small helper to locate a valid BrowserWindowController.

repro:
Open a non-browser Grove window such as the About panel so it is key, then invoke File > New Tab or Cmd+T.

## low: Closing a window persists its state before removing it from restoration

id: fnd_sig-feat-ui-flow-01884210cd-e50c_b1488e42b2
category: bug
confidence: high
triage: confirmed-bug
status: open
feature: Apple source Grove/App (feat_ui-flow_01884210cd)

evidence:
- Grove/App/AppDelegate.swift:75-79 (AppDelegate.windowDidClose(_:))
- Grove/App/AppDelegate.swift:83-85 (AppDelegate.saveWindowStates())

The close notification handler writes the restoration list while the just-closing controller is still in windowControllers. That leaves UserDefaults containing a closed window until a later save happens. Normal Quit may overwrite it, but if the app is relaunched after an unexpected exit or after the process is killed while no later save ran, the closed window can be restored.

recommendation:
Remove the closing controller from windowControllers before calling saveWindowStates(), and consider filtering for controllers with non-nil, non-closing windows when saving.

test analysis:
No linked AppDelegate/window-restoration tests were provided, and the existing discovered tests focus on storage, navigation history, and BrowserWindowController capability validation.

suggested regression test:
Add an AppDelegate restoration test that registers a BrowserWindowController, simulates its close notification, and asserts the persisted windowStates no longer includes that controller.

minimum fix scope:
AppDelegate.windowDidClose(_:) ordering plus a focused window-state persistence test.

repro:
Open a Grove window, close it, and inspect the windowStates UserDefaults value before applicationWillTerminate runs; it still contains the closed window's saved state.

## low: Legacy window-state migration test reimplements the fallback instead of calling the restore path

category: test-gap
confidence: medium
triage: test-gap
status: open
feature: Apple test suite . (feat_test-suite_919fbedeaf)

evidence:
- GroveTests/StorageModelTests.swift:16-21 (testWindowStateMigrationFromCurrentURL)

The test body performs the legacy currentURL fallback inline, so it can pass even if the production window restore code stops applying that fallback. That leaves restored user window state vulnerable to regression without a failing test.

recommendation:
Test the production restore entrypoint with a legacy state dictionary, using an existing temporary directory for currentURL so any directory-existence guard is satisfied.

test analysis:
The existing test asserts the fallback expression embedded in the test, not the production migration behavior.

suggested regression test:
Create a temporary directory, build a legacy dictionary containing only currentURL and other required window-state fields as needed, call BrowserWindowController.restoreState(from:), and assert the resulting controller currentLocation is the expected local StorageLocation.

minimum fix scope:
Replace or supplement GroveTests/StorageModelTests.swift legacy migration coverage with a test of the production restore path.
